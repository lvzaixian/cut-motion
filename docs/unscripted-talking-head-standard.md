# 无脚本口播与截图编排执行规范

本规范来自 09「生活系统」的实际返工与最终确认，适用于之后的无参考稿口播；截图展示部分也适用于有稿视频。它补充既有转写、选段与视觉规范，不新增工作流状态或用户审批点，不追溯改写已完成任务。目标是在用户第一次看粗剪和包装时，先解决已知的原话、表现、素材完整性和语义节奏问题。

## 1. 开始时明确证据与能力

- 记录“有参考稿 / 无参考稿”、完整原片、补录和用户辅助素材。无稿时，原始 ASR、录音核对后的 transcript、发布字幕是三种不同证据；不得把整理过的 ASR 注册成用户提供的参考稿。
- 检查当前 ChatCut 工具、实际可用的本地转写环境，以及本轮是否能直接收听音频或有人工听校路径。工具可见不等于已登录，生成音频或第二次 ASR 不等于已经听过。
- 同时探测原片大小与实际上传/导出状态。对已确认的容量超限或同样输入重复出现的终端错误，记录一次障碍后转向已安装本地 ASR 或现有可审阅回退，不继续盲试同一路径。原生粗剪仍保持可编辑；本地映射底片只在真实来源、倍率与帧映射可核对的范围内使用，并注明原生导出未成功，不绕过现有批准和状态条件。
- 若无法满足当前 reconciliation / roughcut-selection 的真实音频证据要求，在转写阶段就说明缺口、可继续的工作和需要人工核对的范围。继续完整 ASR、内容解析和封面准备；不要直到包装阶段才发现缺口，也不要伪造 `audioChecked` 或选段通过。
- 用户对少数原词、粗剪或成片的确认只覆盖明确确认的范围。09 允许跳过未入成片重录与弃段逐段听校的例外只属于 09，不是后续默认。能力缺口须由真实听校解决，或取得明确限定的新任务例外；没有正式支持的转换时，不能手填工作流完成。

## 2. 无稿内容先分三层处理

| 层次 | 必须解决的问题 | 记录位置 |
| --- | --- | --- |
| 内容 | 全片主旨、钩子、背景与前提、重录组、末次完整表达；区分重试、强调、回扣和递进 | `docs/content-analysis.md`，既有 transcript / reconciliation / selection |
| 表现 | 找词、失败起句、无意义“嗯/额”、眼神游移、翻眼或身体复位是否可与空转一起去除 | `docs/content-analysis.md` 的表现复核；ChatCut 编辑记录 |
| 节奏 | 保留自然呼吸、个人语气和理解停顿，再比较并锁定本期倍率 | 既有粗剪确认，不提前制作正式字幕和包装 |

ASR 没有文字不等于静音；文本流畅不等于画面自然。在给用户看首轮粗剪前，对已发现的停顿、找词和重启位置联合检查声音与连续画面；再通看选中表达的表现连续性，避免只检查剪口而漏掉句内空转。优先把无意义余气和对应的异常眼神作为同一个区间处理，不能只删“嗯”却留下复位尾巴。正常眨眼、自然眼动、修辞停顿不因外观一律删除。检查不足的范围明确标注，不写成全片通过；默认 review 不因此启用完整自动声学审计。

每个剪口仍须保护前后音节、句意与身体接续；边界证据冲突时，使用既有 `inspect-media-window.mjs` 定位，而不是反复盲切。真正重录默认选最后一次完整表达，不跨版本拼造一段未说过的话。

## 3. 原词疑点尽早成批收敛

1. 全片通读后建立一个疑点清单：原片时间与 segment ID、ASR 原文、候选、影响、核对证据和状态。关键术语、否定、数字、代词、收入与因果等优先处理；可疑幻觉单独隔离，不以语境猜测进入封面或字幕。
2. 先在现有能力内复核。局部重转写须保存原片偏移、原始输出和失败结果；两次一致只是自动证据，不能填成人工听校。
3. 仍有歧义时，在正式字幕切分与视觉编排前，把已知疑点合为一次简洁核对：编号、候选原话、带前后语境的短音频和一句所需回答。新证据确实带来新疑点时再追加，不反复询问已确认的词。
4. 用户确认后更新同一清单与既有 reconciliation，并让 transcript、字幕计划和 MG 上屏文案一致。保留确认原句与范围，避免后续重转写重新覆盖。
5. 保留真实口语。“精力”不能被猜成“经验”；说“效果、期待”不能因主题改成“体验”；确认过的“赚了怎么样钱”“他的评价”等不按书面流畅度擅自改写。字幕可清理标点、空转与切分，不能改变主语、含义或补出未说的话。

## 4. 辅助素材在计划前登记齐全

素材入场时先做清单，记录路径/哈希、内容、隐私、能支持的观点以及“拟采用 / 有理由不采用 / 待核对”。用户指定采用的素材应逐项落实；存在隐私、权利或事实冲突时尽早提出，不能默默遗漏。新增素材在合成前重新登记并进入现有视觉编排确认；新增素材节点属于 `motion-plan` 返工。

先按口播含义分组，再决定视觉：作息、饮食、食物清单、健身规划若共同支持健康规划，就属于同一健康证据组；复盘纪要属于复盘；录取结果属于对应经历。不能因为素材文件名不同就拆到多个无关观点，也不能把已经登记的材料摆在错误的段落充数。

入场清单只是编辑依据；实际采用的资产、词锚与时序仍只在 `state/beat-map.json` 登记，确认包由它生成，不新建第二份手写时间表。

## 5. 截图默认完整、大方、仅遮敏感字段

- 个人规划、饮食、健身清单、录取与复盘截图默认保留全图边界并等比 `contain`。优先直接呈现真实页面；不为做动效拆成细条、小碎卡或重画成概念图。
- 隐私按字段遮罩：姓名、头像、电话、账号、申请信息等实际敏感处逐项判断；公开、无隐私且服务当前观点的内容保留。不因一个电话就裁掉大半张截图。
- 遮罩按原图像素定位，与原图放在同一变换容器，随移动、缩放、旋转共同变化；入场、落定与退出都检查覆盖。原图保持不可变，遮罩是合成层。
- 先为截图本体分配足够宽度，再做边框、标题和留白。横图可优先放在字幕上方的上中部，保留其下方人物表达；按当前构图决定位置，不固定复制 09 的 y=280，也不为避脸缩成难辨的小图。
- 如果默认焦点区或证据承载层面积预算容不下完整材料，在 `motion-plan` 先解决：减少无信息背板和留白，重新安排同组构图；仍需任务内布局参数调整时，把实际需求、参数与理由纳入既有视觉包确认。不要先切碎材料来迎合模板，也不要到渲染报错后才扩大边界、改全局默认或取消安全区检查。
- 只有观众任务明确需要看一个字段或细节时才局部放大，计划须写明原因并先保留全图上下文。同组堆叠允许后图自然遮住前图，但每张入场时都应有可辨认的独立展示阶段，不能从第一帧就被盖住。
- 完整显示不等于全页文字已被读完。缩到真实手机观看尺度，至少能辨认页面类别、组织结构和当前关键内容；若要求读具体文字，使用下一节的细读路径，不能宣称快速堆叠满足细读。

## 6. 从词锚、阅读任务和总预算共同定时

### 6.1 先明确观众要看什么

| 阅读任务 | 默认处理 | 验收依据 |
| --- | --- | --- |
| 概貌 / 真实性确认 | 完整图大尺寸、短停留，展示“有规划”“有记录”等结构与真实材料；无需读完全部正文 | 关键结构和当前事实能辨认，按对应口播及时退出 |
| 同组材料的规模与体系 | 逐张快速入场、交叉叠放、前图保留、末图稍停、整组统一退出 | 每张出现、顺序可跟随、最后整组可识别；不拖住后一个观点 |
| 具体字段 / 细节阅读 | 全图建立上下文后局部强调或分阶段阅读，重新安排足够口播窗口 | 在实际观看尺度能读完指定信息；窗口不足就减少同屏信息或改方案 |

入场速度、相邻入场间隔、落定后的停留和整组总窗口须分别决定。短暂证明图不能机械占满整段；密集文件也不能因原图字多就默认长驻。先找对应短语和下一观点边界，再预算阅读与退出。

### 6.2 同组截图的紧凑起点

同组概貌堆叠先试相邻入场约 **0.4–0.65 秒**的紧凑节奏；这是本次偏好的制作起点，不是硬门槛或细读时长。优先贴“作息、饮食、健身”等实际枚举词，词间距和可读性可推翻此范围。子对象快速入场不等于新增独立 MG 段落，不改全片 MG 覆盖频率或用更多装饰凑节奏。

规划时从现有 `objectCues` 计算：

- 相邻间隔：相邻 `preMotionFrame` 的差 / fps；
- 建组耗时：最后对象 `settledFrame` − 第一个对象 `preMotionFrame`；
- 末图落定至整组完全隐藏的余量：共享 `invisibleFrame` − 最后对象 `settledFrame`，其中包含离场动画；稳定阅读时间另按实际离场开始帧减去最后落定帧计算，不能把淡出时间全计入阅读；
- 单图未被后图遮挡的可辨认窗口，以及下一观点开始前是否完全退场。

不能只缩短入场动画，却保留很慢的逐张间隔；也不能把整组窗口压到末图刚出现就退出。若完整建组、关键辨认和退出无法同时满足，优先缩短运动、减少同屏密度或调整方案；不靠让截图提前到无关口播来获得时间。

### 6.3 使用现有可生成字段

阅读目的、展示顺序与整图策略写入 `visualEncoding`、`viewerQuestion` 和 `materialRefs.role/crop`；遮罩写入 `materialRefs.masking`；位置与理由写入既有 `layout`；实际入场、可读、落定与隐藏写入 `objectCues`，均须遵守已有词锚和最大预备帧约束。生成确认包后检查这些说明是否真的出现在表中，以及 cue 推导的间隔和末图停留是否合适。不能只改 `creative-confirmation.md` 模板或生成后的正文：生成器会覆盖它们。

09 最终采用四图约 0.58 秒间隔、保研 1.75 秒、复盘纪要 2 秒，说明这类短概貌窗口可行；它不证明观众读完了全页，也不把这些时长、图数、坐标和 1.25×倍率设为永久默认。

## 7. 先解决局部风险，再生成用户要看的完整版

- 粗剪反馈时先标明用户正在看的版本、时码形式、fps 和倍率。原片时间、粗剪时间、成片时间通过当前映射换算；切段或变速后重新计算，不能沿用旧反馈秒数盲切。必要时用带前后句的候选窗口定位。
- 首次复杂截图组或已发现的遮罩、叠放、词锚/时长风险，可以在已批准计划内做最小的实际编码上下文诊断；包含前一句、入场、完整建组、退出与后一句，必要时超过 1–3 秒。只检查风险组，不给所有节点加样片，不新增默认用户审批。
- 逐图检查实际编码中的入场、首次可辨认、落定、遮罩与完全退出；确认截图未太碎、太小、早入或迟退。源码、静帧排版与“渲染成功”不能证明运动中的效果。没有直接听音能力时，不把可播放诊断写成已人工听过。
- 官方 builder 重建后核对主合成与局部合成使用当前 cue，避免模块已改而主页面仍旧。复用区段遵守既有编码、真实拼接边界、字幕和音轨连续性要求；不能安全复用就整片渲染。
- 用户要求看完整版时，加载当前实际完整候选，并说明文件/版本；局部预览不能代替完整版。保留上一个可用成片；新渲染后重建标题包并核对归档文件。最终确认绑定准确文件，不把旧版批准继承给新版。

## 8. 首次交给用户前的执行自查

这是一轮既有工作中的自查，不是新状态或新表单：

1. 无稿原话和所有已知疑点已处理，未核对范围如实记录；用户确认过的词没有被改回。
2. 末次完整表达、背景、转折、指代和收束仍在；已检查的找词与异常表现没有遗留，倍率已按本期锁定。
3. 用户素材逐项有去向，按对应语义分组；能完整展示的图没有被无理由切碎，敏感字段遮罩随图运动。
4. 截图够大，阅读任务明确；词锚、相邻入场、末图停留和下一观点边界分别合适，不能只检查总时长。
5. 已处理的动态风险有实际编码证据；当前完整候选、批准记录和交付标题哈希一致，保留上一可用版。

这些规则提高第一次交付的把握，不承诺一次审美通过，也不把用户复看变成替 Agent 查已知缺陷。
