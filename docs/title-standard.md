# 平台标题包标准

标题包是成片后的发布准备交付，不是自动发布，也不增加新的用户审批关卡。它的作用是同时提高观众能否快速理解观点，以及平台能否识别视频主题的概率。

## 事实来源与交付

只以已经渲染的 `output/final.mp4`（或待提升的 `output/final.candidate.mp4`）、确认的 `output/cover.png`、锁定字幕和录音支持的开场为事实来源。标题、封面和开头口播必须表达同一核心主题与承诺，但不要求逐字重复。

每个任务必须输出：

- `state/titles.json`：机器可检查的标题包，记录本次成片 SHA-256、工作簿 SHA-256、公开语言检查，以及五个平台各五条候选；
- `output/titles.xlsx`：用户可直接挑选和发布后复盘的工作簿。

一旦成片重新渲染，必须重新生成标题包。检查器会拒绝与当前视频 SHA-256 不匹配的旧工作簿。不要自动替用户选择、填写平台或发布。

## 写作原则

1. 先真实，再抓人：每条标题只能承诺视频、字幕、封面或开头实际支持的内容；可以用成片支持且与主题相关的个人背景或结果作钩子，但不能借此承诺观众也能获得同一结果，更不能补出未经证实的因果或收益。
2. 结合已确认封面和录音开头，优先测试“具体经历或结果＋核心思想或反差”；标题可把封面展开成问题，避免退回泛泛的主题词。一个标题只承载一个观点、问题或可感知收益；自然放入 1–3 个核心关键词，禁止关键词堆砌。
3. 默认把 15–20 个汉字左右作为移动端可读性的编辑目标，而不是平台规则。B站可以更完整地表达命题，但仍把主题词前置。
4. 可测试的钩子包括痛点提问、反常识、身份代入、具体场景、数字和结果；数字/结果只能在成片明确支持时使用。
5. 禁止无依据的 “90%”、 “翻倍”、 “最”、 “第一”、 “绝对” 等夸张或极限表述；符号和 Emoji 只在帮助阅读时使用，不堆叠。
6. 所有标题必须是给观众看的公开表达。不得出现粗剪、封面候选、内部版本、素材待定、待确认等制作语言。

“前 5 字”“前 10 字”“15–20 字”及不同钩子可能提升点击的说法，均视为用户提供的编辑实验假设，不是平台算法、审核政策或效果保证。发布当日的规则与可见指标以平台界面和官方说明为准。

## 平台侧重

| 平台 | 候选默认侧重 |
| --- | --- |
| 抖音 | 主增长阵地；尽早给出观点/冲突，内容确实讨论 AI 时自然包含该主题词，测试直接观点、反常识、痛点提问、身份代入和行动结果。 |
| 视频号 | 清楚、可信、便于转发复述；优先明确结论、现实困境和温和的经验归纳。 |
| 小红书 | 前段自然出现搜索关键词；测试关键词+人群、关键词+场景、关键词+痛点和可执行启发。 |
| B站 | 保留讨论价值和观点密度；优先命题式观点、问题式讨论、反直觉判断和认知解释。 |
| 快手 | 简洁、准确、与内容直接相关；优先清楚、口语化的判断或问题，不做没有事实支持的平台算法推断。 |

同一支竖屏视频跨平台分发时，只调整标题和发布文案，不重做不同内容或不同封面母版。

## 工作簿规范

`标题候选` 工作表必须含五个平台共 25 行：平台、候选编号、候选标题、字数、前置呈现、核心关键词、主要钩子、内容支持、吸引力评分、关键词清晰度、内容匹配度、平台适配度、总分、推荐顺位、用户最终选择、备注。

`发布复盘` 工作表每个平台一行，提供最终采用标题、发布时间、发布链接、可见曝光/播放、可见点击或进入率、可见观看或完播数据、互动数据、结果观察与下一次测试假设。平台不提供的指标留空并注明，不伪造统一口径。

每个平台恰好给出五条实质不同的候选，候选 ID 固定为 `DY-01`…`DY-05`、`SPH-01`…`SPH-05`、`XHS-01`…`XHS-05`、`BIL-01`…`BIL-05`、`KS-01`…`KS-05`。`state/titles.json` 中的每条候选都记录关键词、钩子类型和具体内容支持，工作簿与该记录必须使用同一份候选。
