# 真人观点口播封面标准

## 目的

每条 Cut Motion 口播先完成全片转写与内容解析，再在粗剪前完成一张独立的发布封面。封面只服务发布，不进入视频时间线，也不改变 `output/final.mp4`。

新任务一律使用本标准的 `talking-head-opinion-poster-v2` `2.1.0` 包。旧 `centered-talking-head-yellow-v1` 与既有 `2.0.0` 包仅由检查器保留读取兼容，供已批准任务复核；不得为新任务新建 V1 或 `2.0.0` 封面包。

## 固定视觉语法

- 母版固定为 `1080×1440`、3:4、sRGB、PNG。
- 底图必须是选中源视频静帧的**直接 3:4 裁切**。不抠像、不扩景、不生成背景、不替换场景，也不为了文字牺牲人物状态。
- 标题固定为眼睛上方的两行错位大粗字：第一行暖白，第二行信号黄；左上保留一个小黄破折号。
- 不使用不透明文字底板、上下炭黑渐隐、底部文字、芯片、代码雨、霓虹网格、平台角标、账号标签或无关贴纸。
- 六张最终候选必须复用同一张裁切底图、同一人物位置、同一字体/颜色/描边/阴影/破折号/布局；只替换面向观众的两行文案。

### D05 锁定版式（1080×1440）

这是当前账号的默认版式基准。以后只在人物眼线或平台安全区要求时，将整个标题组做最小整体平移；不得单独压缩字号、收紧行距或增加第三行。

- 字体：`Microsoft YaHei`，`font-weight: 900`，字距 `-3px`，4px 炭黑描边，轻炭黑阴影。
- 第一行：暖白 `#f7f0e8`，`128px`，左 `56px`、上 `86px`。
- 第二行：信号黄 `#ffd500`，`176px`，左 `160px`、上 `266px`；保持 `52px` 的视觉行距。
- 小黄破折号：`56×10px`，左 `56px`、上 `48px`。
- 预留底部 `288px` 为纯人物画面；标题不遮住眼睛、嘴巴或有效手势。

`Microsoft YaHei` 是封面专用本机字体，不改变视频动态图形的得意黑默认字体。开始封面渲染前必须确认该字体可用；缺失时停下让用户决定替代字体，不静默回退或下载。

## 文案原则

文案从 `docs/content-analysis.md` 的主旨、钩子与录音支持的开头提炼；优先考虑“具体经历或结果＋核心思想或反差”，例如本期的“双非到中山／不拼时长”，但不能把经历推广成保证或固定套话。封面、开头与最终标题表达同一主题，允许各自补充不同信息。

每张正式候选恰好两行。具体文案不是流程的固定字段，仍由用户从完整封面示例中判断和选择；不要预设“痛点/问答/对照”等六种固定话术。

AI 账号的默认倾向是在录音或参考稿确实讨论 AI 时，让其中一行自然出现“AI”；这不是机械校验规则，更不能靠堆词替代清晰观点。所有文案都必须受录音或已对齐参考稿支持，不夸大收益、因果、平台、日期或视频未支持的结论。

## 封面检查点

封面在 `transcription` 内、完整转写与内容解析后完成，并须在进入 `rough-cut` 前批准。有脚本也不跳过实录解析，不再因封面尚未选择而阻止转写。

1. 从未剪辑源视频中准备并一起呈现**恰好二十四张**原始静帧。优先自然精神、眼神明确、动作有传达力、曝光稳定、画面清晰且可保住脸和手势的帧。
2. 用户选定一张后，记录精确的 3:4 裁切。先保住人物，再安排标题。
3. 若字体、字号或行距尚未锁定，可在 `checkpoints/` 做单独的**样式校准**。校准可复用同一句文案比较字号/字体/间距，但不计入正式六张候选，也不触发批准。
4. 从选中帧和裁切制作一张无文字的 `coverBase`，方法固定为 `direct-source-crop`；记录其哈希、尺寸和裁切信息。
5. 基于同一 `coverBase` 渲染**恰好六张**完整正式候选。每张都是完整人物封面，使用相同 D05 版式，且两行公开文案彼此实质不同。
6. 用户选择一张正式候选后，导出 `output/cover.png`，将 `state/cover.json` 标为 `ready`，再运行 `node scripts/workflow-state.mjs jobs/<job-id>/state/workflow.json approve-cover --actor user --note "Selected public cover copy"`。
7. 只有 `approve-cover` 成功后，才能执行 `advance` 从 `transcription` 进入 `rough-cut`。

## 记录、检查与交付

`state/cover.json` 的新 `2.1.0` 包记录二十四张原始帧、共享直接裁切底图、六张正式候选、最终选择和哈希。V2 检查器要求六张候选共用同一底图、每张正好两行且不重复，并要求人工记录：人物完整、标题在眼睛上方、缩略图可读、无不透明底板、无深色渐隐和安全区已检查。历史 V1 与 `2.0.0` 包仍要求八张原始帧。

检查器验证文件、路径、尺寸、哈希和元数据；它不能从 PNG 自动判断字体、渐隐或人物状态。因此批准前必须同时检查全尺寸图和缩略预览。

最终只交付 `output/cover.png`。发布时若需要 JPG 或其他比例，只能从这个 PNG 母版派生；不改写母版，也不重渲染视频。
